# SMA model list, planned 2026-10-28; every model moved to the V100 pod on llama.cpp on 2026-11-05.
#
# How to read it
# - A line that starts with "sma" is a command: the V100 batch (the next section). Queue every job, then
#   start the dispatcher on the harness GB10 (`sudo systemctl start sma-dispatcher.service`):
#     grep '^sma queue ' model-list.txt | sh
# - "#SPARK" lines are the Spark plans of 2026-10-28 (vLLM, SGLang, or the Spark's llama.cpp), kept as research
#   with their notes; they are not run. "#DONE" lines already ran on the V100.
# - "sma run ... --reference @REPO:QUANT" is a GGUF quant scored against that repo's full-precision GGUF.
#   Run it by hand after the reference run finishes, with @REPO:QUANT replaced by that run's id
#   (`sma list`). `sma queue add` has no --reference (F8).
# - "#BLOCKED" lines cannot run today. The note above each one names the fix (F1-F9, at the end).
# - "#OPTIONAL" lines are extra legs: base models, more quants, and models outside the requested sets.
# - "#LATER" lines are models to come back to, which SMA cannot measure yet or that nobody has checked.
# - Each model has a short note: architecture, engine, and the dry-run memory plan (weights, context
#   per stream, full-length streams within the Spark's 100 GB; the V100 batch's notes give V100 counts).
#   "Gaps" points to the benchmark gaps (G1-G16, at the
#   end, followed by LiquidAI's LFM3 benchmark table mapped onto SMA).
#
# How checkpoints were picked
# 1. The reference is the BF16 safetensors checkpoint on vLLM.
# 2. When NVIDIA, Red Hat, Unsloth, or the model's author publishes a W4A4 NVFP4 or an FP8+NVFP4 mixed
#    checkpoint, the job is a pair (`queue add-pair`): both legs on one Spark, with KL between them.
# 3. When no pinned safetensors engine serves the architecture, the model runs as GGUF on llama.cpp:
#    the full-precision file as the reference, then a 4-bit file with --reference.
# 4. The tool parser follows the chat template's tool-call format: hermes (JSON inside <tool_call>),
#    qwen3_coder (<function=...> XML), lfm2 (<|tool_call_start|>), gemma4. llama.cpp needs none (--jinja).
#
# What was checked on 2026-10-28, with no Spark run: each pinned image's own architecture registry
# (vLLM 0.21 in nvcr 26.05.post1, SGLang v0.5.10.post1, llama.cpp b11913); SMA's quant check
# (detect_quant and the flag); SMA's GGUF file match and tokenizer match for every --reference; and
# `sma run --dry-run` for the memory plan of every leg.
#
# F1 (pair commands failing) is fixed. Since 2026-11-05 only the V100 batch below runs: "#SPARK" marks the
# Spark lines of the family sections, "#DONE" the lines that already ran on the V100.
